# Credits

`forge` is a **synthesis** — it distills the best, most distinctive *ideas and techniques* from
several excellent open skill sets into one cohesive lifecycle. It does not copy their code or
text; every skill and script here is original. Enormous credit to the projects that shaped it:

| Project | Author | License | What forge learned from it |
|---|---|---|---|
| [Superpowers](https://github.com/obra/superpowers) | Jesse Vincent (obra) | MIT | TDD iron law (delete code written before its test, watch it fail), systematic-debugging (3-fixes → question the architecture), verification-as-honesty, brainstorming hard-gate, no-placeholder plans |
| [skills.sh](https://github.com/mattpocock/skills) | Matt Pocock | MIT | "feedback loop IS the skill" debugging, deletion test + two-adapter seam, Design-It-Twice, two-axis (Standards/Spec) review, ubiquitous-language |
| [Taste Skill](https://github.com/Leonxlnx/taste-skill) | Leonxlnx | MIT | anti-slop frontend: tunable dials, mechanically-checkable bans (em-dash ban, eyebrow rule, banned palettes), pre-flight gate |
| [Anthropic Agent Skills](https://github.com/anthropics/skills) | Anthropic | Apache-2.0 (example skills) | skill-authoring best practices (progressive disclosure, descriptions tuned to fire, explain-the-why), build-a-verification-loop-into-the-skill |
| [andrej-karpathy-skills](https://github.com/forrestchang/andrej-karpathy-skills) | forrestchang | MIT | the four principles (think before coding, simplicity first, surgical changes, goal-driven) with falsifiable tests |
| [ECC](https://github.com/affaan-m/ECC) | Affaan Mustafa | MIT | the continuous-learning / "instinct" idea, eval-driven development (pass@k vs pass^k), author-bias elimination, iterative retrieval, harness-as-the-product thesis |

Ideas and methods (TDD, "design it twice", root-cause-before-fix, pass@k, etc.) are not
copyrightable; this synthesis re-expresses them in original wording. Where these projects'
*text* would be reused, their licenses (mostly MIT/Apache-2.0) require attribution — hence this file.

If you are one of these authors and feel something here crosses from "inspired by" into "too close",
please open an issue and it will be corrected promptly.
